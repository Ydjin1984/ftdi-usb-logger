FTDI/USB Logger -- J2534 proxy (j2534proxy.dll)
===============================================

Компонент второго канала захвата: приложение грузит НАШУ библиотеку как
обычный J2534-драйвер (Pass-Thru 04.04), она форвардит вызовы в настоящий
драйвер и пишет собственный журнал вне процесса приложения. Контракт --
docs\13-j2534-proxy.md, грамматика журнала -- docs\11-capture-grammar.md.


1. Состав каталога
------------------

  j2534proxy.dll        прокси. Для поставки -- x86 (PCMflash и драйверы
                        04.04 32-битные). x64 собирается только для тестов.
  j2534proxy.ini        настройки (см. раздел 3). Рядом с DLL.
  j2534proxy.ini.sample пример настроек с комментариями.
  real_dll.txt          резервный способ задать настоящую библиотеку:
                        первая непустая строка = полный путь к DLL.
  README.txt            этот файл.
  version.rc            ресурс версии (1.0.0.120).
  j2534proxy.def        экспорты: 14 имён PassThru* + NONAME 1377,1378,1379.
  j2534proxy.c          исходник (C, только windows.h + статический CRT).
  build.ps1             сборка x86 и x64 + проверка экспортов через dumpbin.
  tests\smoke.c         дымовой тест x64 (прокси -> fake_j2534.dll -> журнал).
  tests\smoke.ps1       собирает и запускает дымовой тест, печатает журнал.
  out\x86\              результат сборки для поставки.
  out\x64\              результат сборки для тестов.


2. Как включить
---------------

Штатно -- установщиком: он кладёт каталог рядом с ftdi-logger.exe,
заполняет j2534proxy.ini (RealLibrary берётся из уже зарегистрированного
драйвера) и создаёт отдельную запись

  HKLM\SOFTWARE\WOW6432Node\PassThruSupport.04.04\<device.Name>
      Name            = Scanmatik - SM2 Proxy     ([device] Name)
      Vendor          = DaVinci Cyber Engineering ([device] Vendor)
      FunctionLibrary = <app>\j2534proxy\j2534proxy.dll

Штатная запись настоящего драйвера (например "Scanmatik - SM2 USB") не
меняется ни на одном шаге.

Вручную:
  1. скопировать каталог рядом с ftdi-logger.exe;
  2. скопировать j2534proxy.ini.sample в j2534proxy.ini и указать
     RealLibrary (полный путь к настоящему драйверу);
  3. создать запись реестра выше (нужны права администратора);
  4. в PCMflash выбрать адаптер "J2534: Scanmatik - SM2 Proxy".


3. Как выключить и откатить
---------------------------

Выключить, не удаляя файлы (журнал перестаёт писаться, вызовы продолжают
идти в настоящий драйвер -- диагностика не ломается):

  - в j2534proxy.ini: [proxy] Enabled=0
  - или переменной окружения: set FTDI_J2534_PROXY_OFF=1

Снять полностью:

  - удалить ветку HKLM\SOFTWARE\WOW6432Node\PassThruSupport.04.04\
    <device.Name> и каталог j2534proxy;
  - вернуть прежний адаптер PCMflash (установщик хранит его в
    <LogDir>\pcmflash-adapter.bak).

Штатная запись настоящего драйвера не затрагивается, поэтому откат сводится
к удалению нашей записи.


4. Приоритет источников (первый победивший)
-------------------------------------------

  параметр           1                          2                     3
  ------------------ -------------------------- --------------------- --------------------
  настоящая DLL      FTDI_J2534_REAL_DLL        [proxy] RealLibrary   real_dll.txt
  файл журнала       FTDI_J2534_PROXY_LOG       LogDir + имя          %LOCALAPPDATA%\
                     (точный путь)              по шаблону            FTDI_USB_Logger\
                                                                       j2534proxy
  выключение         FTDI_J2534_PROXY_OFF=1     [proxy] Enabled=0     --

Если каталог из ini пуст или недоступен, используется
%LOCALAPPDATA%\FTDI_USB_Logger\j2534proxy, а если недоступен и он -- %TEMP%.
ini читается один раз, на первом вызове; изменение требует перезапуска
J2534-приложения.


5. Журнал
---------

Файл: <LogDir>\proxy-YYYYMMDD-HHMMSS-pid<PID>.log
  - создаётся при первом вызове (не при загрузке DLL);
  - ДОПИСЫВАЕТСЯ, а не перезаписывается;
  - FlushFileBuffers после каждой строки, поэтому журнал жив при падении
    приложения.

Шапка (до первой строки обмена):

  # capture start: label=J2534 proxy
  # proxy: dll="...\j2534proxy.dll" real="...\smj2534.dll" pid=8120 bits=32 active=1
  # wall(start)=2026-11-19 18:56:10.123
  # api: 04.04 dll="j2534proxy.dll" ver="1.0.0.120" path="...\j2534proxy.dll" pid=8120 bits=32 dec=1
  # agent: j2534proxy.dll mode=proxy
  # device: name="Scanmatik - SM2 Proxy" vendor="DaVinci Cyber Engineering"

Строки обмена (та же грамматика, что у Frida-агента, поэтому движок читает
журнал своим decode::parse_capture_line):

  [+0.100000s] J2534 open name="Scanmatik - SM2 USB" dev=1 rc=0 th=8120
  [+0.200000s] J2534 connect-enter dev=1 proto=0x8003 flags=0x1000 baud=57600 th=8120
  [+0.200000s] J2534 connect dev=1 ch=1 proto=0x8003 flags=0x1000 baud=57600 rc=0 gen=1 th=8120 dur=57431
  [+0.300000s] J2534 call ch=1 call=7 op=PassThruIoctl ioctl=0x05(FAST_INIT) rc=0 th=8120 dur=812
  [+0.400000s] J2534 TX ch=1 call=8 i=1/1 n_in=1 n_out=1 th=8120 ts=0 flags=0x0 proto=0x8003 svc=0x27 len=4 dur=812 rc=0 : 00 02 27 7f
  [+0.500000s] J2534 RX ch=1 call=9 i=1/1 n_in=10 n_out=1 th=8120 ts=0 rxs=0x0 proto=0x8003 svc=0x50 len=8 dur=20134 rc=0 : 06 50 03 00 00 00 00 00
  [+0.600000s] J2534 vendor ord=1377 op=0x0 rc=0 th=8120 dur=31
  # proxy stop: calls=2876 tx=1959 rx=3917 errors=0

Правила:
  - время -- от загрузки DLL, ровно 6 знаков после точки;
  - hex -- строчными через пробел, ровно DataSize байт; при
    DataSize > MaxDataBytes hex обрезается и пишется truncated=1
    (len= при этом остаётся настоящим);
  - svc= пишется только когда он однозначен: proto >= 0x8000 -> Data[2]
    (при DataSize > 2), ISO15765 (0x06) -> Data[0], иначе ключа нет;
  - rc=0 при успехе и rc=0x11/0x08/... (hex) при ошибке -- как у агента;
  - call= -- сквозной счётчик вызовов процесса, с 1;
  - dur= -- микросекунды (QueryPerformanceCounter), th= -- GetCurrentThreadId();
  - errors= в строке "# proxy stop:" -- число вызовов с rc != 0, включая
    штатные ERR_TIMEOUT (0x11) и ERR_BUFFER_EMPTY (0x10) при опросе: так же
    считает движок (docs/13 §8: errors = вызовы с rc != 0).


6. Провал настоящей библиотеки
------------------------------

  RealLibrary пуста / файла нет   -> "# proxy fatal: real library not found",
                                     все вызовы возвращают 0x08
                                     (ERR_DEVICE_NOT_CONNECTED), журнал пишется
  RealLibrary == сама прокси      -> "# proxy fatal: real == self",
                                     все вызовы 0x08 (защита от рекурсии)

Приложение при этом не падает: оно получает штатную ошибку J2534, а журнал
объясняет причину.


7. Метка "прокси работает" для Frida-агента
-------------------------------------------

При инициализации (до LoadLibrary настоящего драйвера) прокси создаёт
именованный мьютекс

  Local\FTDI_J2534_PROXY_<pid>

и пишет в шапку active=1. Агент по этой метке понимает, что настоящий
драйвер загружен именно прокси и его нельзя хукать второй раз (иначе каждый
кадр попадёт в лог дважды). Хэндл живёт до выгрузки DLL. Если прокси
выключен (Enabled=0 / FTDI_J2534_PROXY_OFF=1), мьютекс не создаётся и
журнал не пишется -- тогда полосу ведёт Frida.


8. Вендорные ординалы 1377-1379
-------------------------------

Настоящий драйвер экспортирует три недокументированных entry point, которыми
PCMflash пользуется для вендорного K-line протокола. Прокси экспортирует их
теми же ординалами:

  - x86: прозрачный naked-танк -- пишет строку "J2534 vendor" и делает
    jmp на настоящий ординал; стек остаётся стеком вызывающего;
  - x64: заглушки, возвращающие 7 (ERR_FAILED) -- вендорного протокола для
    64 бит нет.

Ограничение: танк уходит в настоящую функцию до её возврата, поэтому rc в
строке "J2534 vendor" не наблюдается и пишется как rc=0 (форма контракта).
Если у настоящего драйвера ординала нет, танк возвращает 7 и снимает два
аргумента со стека, а не прыгает в NULL.


9. Сборка и проверка
--------------------

  powershell -ExecutionPolicy Bypass -File proxy\build.ps1
      -> out\x86\j2534proxy.dll (поставка) и out\x64\j2534proxy.dll (тесты)
      -> dumpbin /exports: 14 имён + ординалы 1377,1378,1379
      -> при расхождении exit 1

  powershell -ExecutionPolicy Bypass -File proxy\tests\smoke.ps1
      -> собирает x64, гоняет tests\smoke.exe над
         tests\e2e\fake_j2534\target\release\fake_j2534.dll,
         проверяет шапку, open/connect/TX/RX/call/stop, форму строк,
         точный hex и то, что журнал дописывается, а не перезаписывается
      -> журнал прогона: proxy\tests\out\smoke.log

Зависимости DLL: только KERNEL32.dll (CRT слинкован статически, /MT).
Версия ресурса 1.0.0.120 совпадает с PROXY_VERSION в j2534proxy.c -- при
изменении править оба места.
