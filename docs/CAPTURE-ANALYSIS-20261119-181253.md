## Что показал лог по существу

Приложение шагов не размечает (`steps: 0`), обмен идёт **двумя короткими
попытками**:

| Отрезок | Время | Длительность | Посылок | TX / RX | Сервисы запросов |
|---|---|---|---|---|---|
| 1 | 3.64–4.11 с | 0.47 с | 52 | 4040 B / 365 B | `0x80×49`, `0x27×2`, `0x10×1` |
| 2 | 26.63–29.12 с | 2.50 с | 58 | 4061 B / 419 B | `0x80×49`, `0x27×5`, `0x82×3`, `0x10×1` |

Между ними — **22.5 с простоя** и перезагрузка `smj2534.dll` (вторая `# hooks`
строка, `chan-miss` с новым `mod=`).

В каждой попытке: `0x27 0x7F` (запрос seed) → `0x67 0x7F` + 8 байт seed →
`0x27 0x80` с 128-байтным ключом → `0x67 0x80` → `0x10 0xFA` (flash-сессия) →
49 кадров `0x80` по 245–251 B с подтверждением `0xC0` на каждый → `0x82` →
`disconnect`. Суммарный TX 8 КБ — это не запись флеша; приложение дважды
прервалось на одном и том же месте.

## Четыре дефекта отчёта (закрыты в 0.3.7)

1. **Сеть считалась обменом шины.** `RX 1706 B` в шапке = 784 B адаптера + 922 B
   HTTP-пробы лицензии (`10.0.0.118:54009 → 45.132.18.119:80`). Больше половины
   «RX» не имело отношения к ЭБУ. Теперь `counts.tx/rx/tx_bytes/rx_bytes` — только
   адаптер, сеть — `net_tx/net_rx/net_bytes` и строка «Сеть (не шина), байт».

2. **Транспорт врал: `vcp` при живом J2534.** Значение инициализируется догадкой
   «`ftd2xx` не загружен → `vcp`», а пересчитывалось только в
   `api::detach_finalize`. Сессия закончилась выходом приложения — отчёт остался
   с догадкой. Теперь `transport_summary` считается в `finalize`, до отчёта.

3. **841 байт «принятых» из чужой памяти.** Событие `LAN RX len=841` содержало
   обрывки UTF-16-путей (`ral__8wekyb3d8bbwe`) и сотни нулей: `lanSweep` брал
   счётчик из `OVERLAPPED.InternalHigh`, не проверяя статус завершения, — там
   осталось значение прошлой передачи. Теперь статус обязан быть успешным
   (`Internal & 0xC0000000 == 0`), счётчик больше буфера отбрасывается со
   строкой `LAN WARN …`.

4. **Пустая Mermaid-схема и `calls=0`.** `flowchart TD Start → End` при
   «Шагов 0» — заглушка; вместо неё раздел «Обмен» и факты `# обмен …`.
   А `# counters … calls=0` при 330 вызовах означало «счётчики агента не
   доехали»; теперь есть поле `agent_counters=0/1` и явный факт в отчёте.

## Чего в логе нет принципиально

* `PassThruConnect` — приложение его не зовёт, канал открывает драйвер
  (`chan-miss`, см. `docs/12` §11).
* Три экспорта `smj2534.dll` без имени (ординалы 1377–1379) — `enumerateExports()`
  их не отдаёт, они не хукаются.
* `LAN TX` — исходящих пакетов в логе нет: запрос ушёл до хуков либо не через
  `send()`; видны только ответы сервера.
